# V1 L4/L2-3 SNN

This repository now targets a GeNN C++ implementation of a two-layer V1 model.
The primary path is a generated-code workflow for NVIDIA GPUs on the H200 pod,
with fixed L4 orientation-tuned drive, explicit E/I populations in `L4` and
`L2/3`, local L4 to L2/3 convergence, and local recurrent structure.

## Model summary

- Two retinotopic sheets: `L4` and `L2/3`.
- Explicit excitatory and subtype-specific inhibitory populations in both
  sheets: `L4PV/L4SOM` and `L23PV/L23SOM/L23VIP`.
- Fixed L4 excitatory drive generated analytically in C++ from deterministic
  simple-cell-like orientation tuning.
- Local L4 to L2/3 convergence with a soft probabilistic orientation prior
  rather than a hard same-orientation mask.
- Local sparse plastic `L23E -> L23E` recurrence with cell-level response
  correlation and strong-synapse enrichment diagnostics.
- PV and SOM inhibitory pathways with homeostatic plasticity; SOM has broad
  output geometry and size-tuning/SOM-output-ablation validation.
- Orientation-sweep, cell-tuning, OSI, context, size-tuning, recurrent
  specificity, recurrence-ablation, and subtype-rate exports.

## GeNN C++ quick start

The primary scaffold lives under `genn/`:

- `genn/v1TwoLayerModel.cc`
  Contains `modelDefinition(ModelSpec&)`, population declarations, local sparse
  connectivity snippets, the baseline/post orientation sweep, and gated
  `L4E -> L23E` STDP training inside `simulate(...)`.
- `genn/v1GenerateL4Drive.cc`
  Dependency-free C++17 generator for deterministic `L4E` drive vectors from a
  grating orientation. It is useful for inspecting the fixed L4 drive but is
  no longer the primary experiment path.
- `genn/v1TwoLayerSimulation.cc`
  Legacy standalone runner from the older generated API. It is kept for
  reference but is no longer the recommended GeNN 5.4 smoke path.
- `genn/v1TwoLayerConfig.h`
  Shared population counts and subtype-specific LIF/connectivity parameters.
- `genn/v1Biology.h`
  Shared deterministic orientation-map and L4 simple-cell drive helpers.

Build and run with the standard GeNN C++ workflow:

```bash
cd genn
V1_ORIENTATION_COUNT=12 \
V1_TRIAL_MS=250 \
V1_SETTLE_MS=50 \
V1_TRAINING_EPOCHS=1 \
V1_STDP_APLUS=0.0001 \
V1_STDP_AMINUS=0.0000875 \
V1_OUTPUT_PREFIX="$PWD/v1_experiment" \
genn-buildmodel.sh v1TwoLayerModel.cc
```

Notes:

- `v1TwoLayerGenn_CODE/` is generated by `genn-buildmodel.sh`.
- `simulate(...)` inside `genn/v1TwoLayerModel.cc` is the primary GeNN 5.4
  experiment entrypoint. It performs:
  - a baseline orientation sweep
  - gated `L4E -> L23E` STDP training over repeated orientation trials
  - a post-training orientation sweep
- If unset, the experiment falls back to:
  - `V1_ORIENTATION_COUNT=12`
  - `V1_TRIAL_MS=250`
  - `V1_SETTLE_MS=50`
  - `V1_TRAINING_EPOCHS=1`
  - `V1_STDP_APLUS=0.0001`
  - `V1_STDP_AMINUS=0.0000875`
  - `V1_OUTPUT_PREFIX=/scratch/proj/v1_snn_l4_l23/genn/v1_experiment`
- Optional subtype perturbation gates:
  - `V1_L23PV_GATE_NA`
  - `V1_L23SOM_GATE_NA`
  - `V1_L23VIP_GATE_NA`
- Main outputs are written as CSV/text files with the chosen prefix:
  - `*_baseline_l4_sites.csv`
  - `*_baseline_l23_sites.csv`
  - `*_post_l4_sites.csv`
  - `*_post_l23_sites.csv`
  - `*_weights_before.csv`
  - `*_weights_after.csv`
  - `*_subtype_rates.csv`
  - `*_summary.csv`
  - `*_summary.txt`
- The auxiliary `v1GenerateL4Drive.cc` utility is still available when you want
  to inspect a single deterministic `L4E` drive vector outside the full sweep.

## H200 pod workflow

Only `/scratch` is persistent on the pod. Treat it as your working home for
code, build artifacts, environments, logs, and outputs.

```bash
mygpu up
mygpu connect
cd /scratch/proj/v1_snn_l4_l23
tmux new -s v1-genn
cd genn
PKG_CONFIG_PATH=/scratch/miniconda3/lib/pkgconfig \
CUDA_PATH=/usr/local/cuda \
LDFLAGS="-L/usr/local/cuda/lib64/stubs" \
V1_ORIENTATION_COUNT=12 \
V1_TRIAL_MS=250 \
V1_SETTLE_MS=50 \
V1_TRAINING_EPOCHS=1 \
V1_STDP_APLUS=0.0001 \
V1_STDP_AMINUS=0.0000875 \
V1_OUTPUT_PREFIX=/scratch/proj/v1_snn_l4_l23/genn/v1_h200 \
/scratch/v1_l4_l23/smoke/genn/bin/genn-buildmodel.sh v1TwoLayerModel.cc
```

The validated subtype full run on the H200 used the default experiment settings
above. It produced `baseline_l23_median_osi=0.141110`,
`post_l23_median_osi=0.826583`, and a matched zero-training control with
`post_l23_median_osi=0.148311` and unchanged mean plastic weight
`0.005743 -> 0.005743`.

The newer soft-prior/SOM/recurrence audit is documented in
`docs/v1_soft_prior_som_recurrence_report.md`. Its current validated run uses
`V1_FF_ORIENTATION_BIAS_STRENGTH=0.3`, passes L2/3 OSI
(`full_post=0.745356`, `control_post=0.000000`), passes SOM size tuning and
SOM-output-ablation gates, and passes recurrent specificity, strong-synapse
enrichment, and recurrence-output-ablation gates.

The latest scaling/L4 inter-site audit is documented in
`docs/v1_l4_intersite_scaling_report.md`. It adds opt-in sheet scaling,
distributed validation sites, and weak local L4 inter-site E/I spread. The
validated `32x32` L4 inter-site run passes all strict gates; the `40x40`
L4 inter-site run passes L4/SOM/PV/recurrent gates and responsive-site OSI, but
still has a strict all-site L2/3 OSI near-miss due sparse responsive coverage.

The cell-level coverage follow-up is documented in
`docs/v1_cell_responsive_coverage_report.md`. With multi-phase held-out
coverage measurement and `V1_TRAINING_EPOCHS=2`, the `40x40` L4 inter-site
model passes strict OSI and raises L23E peak-responsive cell coverage to
`32.2%`, while preserving L4/SOM/PV/recurrent gates.

The pre-feedback higher-area predictor milestone is documented in
`docs/hva_predictor_system_report.md`. The validated run
`v1_hva_pred18_l23_topk_weighted_delay8_som051_256f` adds a default-off,
predictor-only HVA sidecar that reads causal L23E history and predicts the
future top-k L23E tile activity pattern 8 video frames ahead. It uses no
HVA-to-V1 feedback, no L4/PV/SOM target shortcut, no future inputs, and no
lower-V1 mutation. The final H200 validator returned `rc=0` with no `FAIL`
lines; key held-out top-k metrics were `model_recall_at_k=0.269048`,
`persistence_recall_at_k=0.195238`, `train_frequency_recall_at_k=0.215476`,
and `model_chance_ratio=5.380952`.

The current population-state validation milestone is documented in
`docs/release_state_20260610_l23_population_state.md` and
`docs/l23_population_state_dev2_validation_report.md`. The latest dev2 run
`v1_l23_popstate4_dev2_20260609T154837Z` validates repeated natural-video
L2/3E population states in the central `32x32` core of a `40x40` sheet. It
passes strict gates for repeat population-vector reliability
(`repeat_vector_corr_mean=0.672147`), odd/even representational geometry
(`odd_even_rsm_corr=0.901051`), and held-out-repeat decoder transfer
(`heldout_decoder_top1_accuracy=0.750000`,
`heldout_decoder_top5_accuracy=0.996094`), with HVA/top-down feedback disabled.
This is the preferred biological target for the next higher-area predictor;
exact top-k tile identity is retained only as a diagnostic stress test.

Zero-training subtype perturbation checks used `V1_L23*_GATE_NA=0.2` one at a
time. Relative to the no-gate control, PV and SOM gates suppressed mean L2/3E
rate (`29.63 Hz -> 11.02 Hz` for PV, `29.63 Hz -> 17.22 Hz` for SOM), while
VIP gate disinhibited L2/3E (`29.63 Hz -> 38.54 Hz`) and reduced SOM activity
(`59.47 Hz -> 34.50 Hz`). These are functional wiring checks, not full
center-surround biology validations.

Operational reminders:

- Do not rely on disconnecting to stop billing; use `mygpu suspend` or
  `mygpu down`.
- Use `tmux` for long runs after `mygpu connect`.
- If you need a CPU-only debug build, use `genn-buildmodel.sh -c v1TwoLayerModel.cc`.
